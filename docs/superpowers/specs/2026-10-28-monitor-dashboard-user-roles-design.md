# 监控台普通用户与删除权限设计

## 目标

新增一个独立的普通用户账号。普通用户与现有管理员共享监控台数据并能使用正常业务功能，但不能删除或移除监控数据、清空商品池、删除店小秘失败记录或取消剩余采集队列。

## 已确认的要求

- 采用数据库角色与监控台内的管理员账号管理，不采用固定环境变量配置的第二个账号。
- 管理员与普通用户查看同一份监控数据，不按用户隔离店铺、商品、采集结果或队列。
- 普通用户可查看、添加、编辑和采集。
- 普通用户不得删除店铺或商品、停用监控、清空商品池、删除店小秘失败记录或取消剩余采集队列。
- 受限操作既要从普通用户界面隐藏，也必须由后端拒绝，不能仅依赖前端隐藏按钮。
- 管理员可以创建、停用和重置普通用户账号；普通用户不能管理其他账号。
- 停用账号时保留账号记录并立即撤销其现有会话。
- 新账号首次登录必须修改初始密码；普通用户可修改自己的密码。
- 不通过聊天传递密码或其他账号凭据。
- 本设计不包含部署或重启 NAS 服务。

## 当前实现

- `app/db/models.py` 已有 `User` 与 `AuthSession` 数据模型及数据库会话。
- `app/core/auth.py` 使用 `AUTH_ADMIN_USERNAME` 识别当前配置管理员；当前用户认证依赖没有角色概念。
- `app/api/router.py` 的业务 API 路由普遍要求登录，但除店小秘失败记录删除外，尚无统一的操作级权限。
- 店铺和商品的“删除监控”实际是软停用；商品池清空也通过批量设置商品为 inactive 实现。因此必须同时保护停用 API、批量清空 API 和可直接写入 inactive 状态的编辑 API。
- 登录会话保存在 `auth_sessions`，现有密码哈希使用 scrypt。

## 角色模型

| 角色 | 能力 |
| --- | --- |
| `admin` | 全部业务操作、账号管理、删除和清理操作 |
| `operator` | 共享数据的查看、添加、编辑、采集、审核及普通队列操作；无删除、停用、清空和队列整体取消权限 |

现有配置的管理员账号继续作为唯一管理员。账号管理界面只能创建普通用户，不提供提升角色或创建额外管理员的入口。管理员不能停用或重置自身账号。

## 账号生命周期

1. 管理员在监控台输入新账号名称并创建普通用户。
2. 后端生成一次性初始密码并设置首次登录改密标记。初始密码只在创建响应中显示一次；数据库只保存 scrypt 哈希。
3. 新用户首次登录后必须先设置自己的密码，未完成改密前不能访问监控数据或调用业务 API。
4. 管理员可为普通用户重置密码。重置后，系统生成新的初始密码、要求首次登录改密，并撤销该用户所有既有会话。
5. 管理员停用账号时，账号记录保留，账号不能继续登录，所有活动会话立即撤销。
6. 普通用户只能修改自己的密码；不能注册、停用账号、重置他人密码或查看密码哈希。

## 权限执行

后端为已认证用户解析角色，并提供管理员权限依赖。所有业务 API 保留现有登录要求；新增权限检查覆盖以下操作：

- 店铺或商品停用，以及通过 `PATCH` 直接把状态改为 `inactive`。
- 批量清空活跃监控商品。
- 删除单条或批量店小秘失败记录。
- 取消剩余浏览器采集队列，以及任何会清空/替换监控池的批量操作。
- 创建、停用、重置其他账号。

普通用户对受限 API 的请求返回 `403`。权限必须基于数据库中的用户角色校验，不能信任客户端传来的角色字段。现有采集扩展继续使用当前登录账号签发的会话；普通用户会话具有 operator 权限，不会因扩展请求获得管理员权限。服务间令牌仅保留其已有、路径受限的集成用途。

只把任务标记为取消且保留队列记录的单条任务取消，若不清除其他任务或监控数据，仍按普通队列操作处理；取消整条剩余队列属于受限操作。

## 页面与 API

- `/api/auth/me` 返回用户角色及首次登录改密状态，页面按角色渲染可用操作。
- 新增仅管理员可访问的账号管理页面，列出普通用户的用户名、状态和创建时间，并提供创建、停用、重置密码操作。
- 普通用户看不到受限按钮、批量清空控件或账号管理入口。
- 新增账号管理 API，所有端点单独要求管理员角色；密码只在创建/重置成功响应中返回一次。
- 新增首次登录密码设置页面及修改本人密码 API。强制改密期间，后端拒绝其他页面和业务 API 请求。

## 数据迁移与兼容

- 新增 Alembic 迁移，为 `users` 增加角色和首次登录改密状态字段；默认角色为 `operator`，现有配置管理员在应用启动时被标记为 `admin`。
- 不删除或重写监控数据、采集队列、会话历史或其他现有表数据。
- 保持当前配置的管理员用户名作为管理员身份的引导来源，避免现有管理员被降权。
- 已有非管理员账号迁移为普通用户；迁移不重置其密码。

## 验收标准

- 现有管理员可以创建普通账号，查看一次性初始密码，并成功停用或重置普通账号。
- 普通账号首次登录必须修改密码；停用后旧会话立即失效。
- 普通账号能读取共享监控数据，添加、编辑和采集业务对象，并使用普通队列功能。
- 普通账号在页面中看不到删除、停用、清空、整队取消及账号管理操作。
- 即使绕过界面直接请求受限 API，普通账号仍收到 `403`，数据库状态不发生变化。
- 管理员仍可完成原有全部操作；普通用户不能变为管理员。
- 数据库迁移为增量迁移，现有监控数据和采集队列保持不变。

## 不在范围内

- 按用户隔离监控数据或采集队列。
- 邀请邮件、自助注册、单点登录或第三方身份提供商。
- 多级权限、可自定义权限矩阵或额外管理员角色。
- NAS 公网入口、TLS/反向代理配置、Docker 部署或服务重启。
- 任何自动执行采集、恢复队列、迁移数据库或部署服务的动作。
