# 主采集电脑与辅助采集电脑设计

**状态：** 待用户审阅
**日期：** 2026-11-01
**范围：** 每日浏览器采集队列
**补充：** `2026-10-31-shared-browser-collection-workers.md`

## 背景

现行共享队列在人工启动后允许所有在线 worker 领取任务。启动前选择的电脑只作为启动授权，不是任务领取范围。扩展在电脑上保持在线即可自动领取，因此即使用户只在 QX 电脑上启动，Galore 电脑也可能收到任务。

用户确认的新规则是：每轮由启动前选中的电脑担任主采集电脑并锁定；可以同时启用多台辅助电脑；辅助电脑选择中排除本轮主机；未明确启用的在线电脑不能领取本轮新任务。

## 目标与边界

- 按每轮采集运行保存主机和辅助 worker 名单。
- 只有本轮名单内且在线的 worker 能领取新任务。
- 保留多台电脑并发处理不同任务的能力。
- 保留已领取任务的 worker、claim token、租约及结果校验关系。
- 不改变店铺身份核验、监控池、店小秘队列、每台电脑最多两个采集页等既有行为。
- 不自动开始、取消、重置或重排当前队列。

## 角色与数据

### 主采集电脑

用户在首次手动启动时从在线电脑中选择主机。后端在开启派发的同一事务中将该 worker ID 保存到 `BrowserCollectionRun.primary_worker_id`。本轮开始后主机锁定；切换控制台的未来启动选择不会改变当前运行的主机。下一轮可重新选择。

首次启动必须有在线主机。主机在运行中离线时，已授权且在线的辅助电脑仍可领取新任务；若没有任何授权电脑在线，待处理任务保持在队列中。

### 辅助采集电脑

用户可在启动前多选已登记的电脑作为辅助机。辅助机按 worker ID 保存于 `browser_collection_run_helpers` 关联表。选择器不提供本轮主机，防止同一电脑同时处于两个角色。离线电脑可保留在名单中，但只有恢复新鲜心跳后才能领取。

主机和辅助名单属于单轮配置。首次启动后保持不变；开始后的选择变更不会扩大当前运行的领取范围。若旧运行尚无角色记录，其第一次按新规则恢复时可提交一次主机和辅助名单；保存后即锁定。

若旧运行已经开启派发但尚无角色记录，控制台仍提供手动“锁定本轮主辅电脑”操作；只有用户点击后才分配角色，迁移本身不改变派发状态。

### 持久化结构

- `browser_collection_runs` 增加可空 `primary_worker_id`，引用 `browser_collection_workers.worker_id`。
- 新增 `browser_collection_run_helpers(run_id, worker_id)`，以复合唯一键避免同一辅助机重复加入，并引用运行与 worker。
- 创建辅助名单时由服务层拒绝未知 worker、重复 worker 以及与主机相同的 worker。
- 现有 worker 名称覆盖、心跳和在线状态逻辑保持不变。

## 启动、领取与结果流程

1. 队列待启动时，控制台提供主机选择器和辅助机多选器。选择辅助机时排除主机，并显示各 worker 的在线状态。
2. 用户点击“开始采集”时，控制台将辅助 worker ID 列表随启动请求发送。后端确认主机在线、辅助 ID 已登记且不包含主机，在同一事务中保存本轮角色后开启派发。
3. 领取接口只允许当前运行的主机或辅助名单中的在线 worker 领取 `PENDING` 项目。未授权 worker 按无任务处理，不得获得任务或 claim token。
4. 多个获准 worker 仍可并发领取不同项目；现有数据库锁继续确保一个项目只会授予一个 worker。
5. 结果提交和心跳续租仍按原 `claimed_worker_id`、claim token 和有效租约验证，不因该 worker 不在新领取名单而取消已有领取。
6. 暂停和平台验证仍是整个队列的闸门。恢复时沿用该轮角色。尚无角色记录的旧运行可在首次恢复请求中登记一次角色；已有 claim 仍保留原 owner。租约过期并退回队列的项目只能由本轮授权 worker 重新领取。

## API 合同

- `BrowserCollectionRunRead` 暴露本轮主机及辅助 worker ID；控制台据此显示已锁定角色。
- 首次 `start-today` 请求携带 `helper_worker_ids`；主机继续取自已选的在线电脑。
- 已有角色的运行在 `resume` 时沿用已保存名单，不接受角色替换。尚无角色记录的旧运行可在首次 `resume` 中提交 `helper_worker_ids`，主机取自当前选择并与辅助名单一并保存。
- 角色锁定后，当前运行的主机选择器不可修改；它只为下一轮设置启动电脑。
- 初次启动要求主机在线。已锁定运行恢复时，主机或至少一台辅助机在线即可恢复；若没有授权电脑在线，后端保持派发关闭并返回明确错误。

## 已存在运行与迁移

迁移只添加运行角色字段和辅助关联表，不修改队列运行状态、派发标志、项目状态、租约、owner、claim token 或采集数据。旧运行在首次按新规则启动或恢复时才登记角色，不根据可变的全局电脑选择猜测历史主机。

旧运行第一次按新规则恢复时，用户从控制台选择 QX 作为该轮主机，并可同时选择辅助名单。这个首次角色登记只影响后续新领取；已有 QX/Galore claim 继续由原 worker 完成。已有 claim 过期后，如果该 worker 未列入本轮授权名单，该项目回到队列后只能由主机或已启用的辅助机领取。

当前 NAS 队列含有尚未结束的领取。部署前必须重新只读检查状态；保留现有工作，不在仍有 `RUNNING` 或 `NEEDS_VERIFICATION` 项目时重建 backend。部署仅更新 backend，迁移不得启动、取消或重排队列。

## 控制台

- 将现有选择改为“主采集电脑”，启动后显示为锁定状态。
- 新增“辅助采集电脑”多选器，只列出主机以外的已登记 worker；离线 worker 标注离线，不能领取。
- 运行中展示本轮主机、辅助名单、在线状态和每台已领取项目数。
- 启动后锁定本轮角色选择；未来启动选择不能被误认为当前队列成员配置。
- 更新提示语，明确只有主机与已启用辅助机可以领取当前队列。

## 错误处理与安全

- 未选择主机、初次启动的主机离线、辅助名单包含主机或未知 ID 时，启动失败并保留队列未派发状态。
- 已锁定的运行尝试更改主辅名单时返回冲突响应，保留原角色和任务。
- 在线但未授权的扩展继续发送心跳，但领取接口不给它新任务。
- 不允许角色变更清除、转移或伪造已有 claim；项目结果仍由原 worker 和 token 决定。
- 没有授权 worker 在线时不派发；扩展重新上线后才恢复领取。

## 验收

### 自动化验证

- 主机可领取；在线但未列入辅助名单的电脑不能领取。
- 多台已选辅助机能分别领取不同项目；本轮主机不能重复出现在辅助名单。
- 非授权 worker 无法领取过期后重新入队的项目。
- 已有 claim 的 owner 即使不在本轮新领取名单中，仍可提交有效结果；过期 token 仍被拒绝。
- 暂停、验证、恢复保持本轮角色；无授权 worker 在线时不发放新 claim。
- 数据库迁移不改已有运行和项目状态。
- 控制台在启动前允许设置角色，启动后显示锁定主机和辅助名单。

### NAS 现场验收

- 在不会打断当前队列的维护边界部署 backend 和迁移。
- 将当前运行主机记录为 QX；让用户显式选择本轮辅助电脑。
- 验证 QX 与每台已启用的在线辅助机能领取不同项目；未选电脑保持零新领取。
- 验证健康状态、迁移版本和队列状态；不自动开始或恢复采集。现场验收与自动化测试分别报告。

## 未包含

- 不按监控台登录账号绑定电脑；电脑身份继续使用稳定 worker ID。
- 不自动把所有在线电脑加入辅助名单。
- 不在本设计中改变当前仍在处理的 claim 或要求扩展升级。
