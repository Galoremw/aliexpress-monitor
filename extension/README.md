# Chrome Extension Browser Collector

这个扩展支持人工补采，以及独立 Chrome 配置中的每日顺序采集。所有渠道都只读取公开可见数据，并写入新的 Snapshot。普通本机监控台不会启用队列 worker；本机 worker 只在带有 `browser_collection=1&browser_collection_profile=isolated` 的 `BrowserCollectorProfile` 中启用。局域网 worker `192.168.66.107:3000/?browser_collection=1` 保持支持。

1. 打开监控台商品详情页，点击“在 Chrome 打开”。
2. 在 Chrome 商品页手动完成 AliExpress 验证（如页面要求）。
3. 在 Chrome 加载当前 `extension/` 目录：打开 `chrome://extensions`，启用“开发者模式”，点击“加载已解压的扩展程序”；如果已经安装，点击“重新加载”。
4. 在扩展详情的“网站访问权限”中允许访问 AliExpress，至少选择“在 aliexpress.com 上”。
5. 回到商品页并刷新。商品页右上角会自动出现“AliExpress 监控采集”浮层；点击浮层中的“采集当前商品”。重新加载扩展后，即使商品页已经打开，扩展也会尝试自动注入浮层。监控台生成的商品链接会携带一个仅供插件识别的监控商品标记，即使 AliExpress 将页面商品 ID 重定向，也能匹配回原监控商品。

说明：Chrome 不允许网页自动打开浏览器工具栏里的扩展 action 弹窗，因此这里使用页面右上角的浮层作为自动弹出界面。工具栏图标仍可用于手动打开扩展菜单。

店铺商品入池：在 AliExpress 店铺商品页先按 `Orders` 排序，点击扩展中的“按近 7 日增量筛选并入池”。扩展每页读取最多 30 个候选的 IXSPY 图表；第一页存在下一页时至少读取第二页，之后若完整七日历史仍不足 20 件则继续翻页。某些商品没有图表或图表未读完整，不会阻塞翻页，也不会按 0 或 Orders 排名补位；只在完整的七日历史中按增量合计降序排名，分数相同按 Orders 顺序。按提示手动切换到下一页后再次点击按钮；读到最后一页仍不足 20 件完整历史时不提交，现有监控池保持不变。店铺实际不足 20 件时，只有全部候选历史完整才会提交较小监控池。同一页可重读以刷新 IXSPY 尚未加载完整的数据。提交成功后只停用未入选的活跃商品，历史快照保留。“测试下一件商品（不提交）”仍可逐件检查读取效果。

人工采集时，扩展只在用户主动点击后读取当前标签页的公开可见信息，并调用配置文件中的 Backend：

```text
POST <BACKEND_URL>/api/collection/browser-extension
```

## 每日自动采集

项目根目录的 `install-browser-collector.bat` 会创建每天 `02:00` 运行的 Windows 计划任务。任务通过 `scripts/open-browser-collector-chrome.ps1` 在 `%LOCALAPPDATA%\AliExpressMonitor\BrowserCollectorProfile` 启动或复用独立 Chrome，并加载本目录扩展。首次运行 `start-browser-collector.bat` 后，从任务栏打开独立窗口，由用户登录监控台、AliExpress 和 IXSPY；日常 Chrome 不会领取队列，也不会被启动器关闭。Backend 每天 `02:00` 只建立待启动的店铺页队列，不会自动开始采集。定时队列只读取已入池商品，不刷新前 20 商品池。

要派发当天队列，在监控台“每日浏览器采集”中先选择在线电脑，再单独点击“开始采集”。只有当前选中的电脑可以领取；选择不会自动开跑，也没有自动故障切换。换电脑时，等旧任务结束后重新选择新电脑并点击开始。`立即采集全部` 和“重新检查今日任务”只准备/刷新队列，不会唤醒采集 worker。浏览器扩展需要使用支持 worker identity 和 claim token 的新版本；旧版扩展不能领取受控队列。

每个店铺只有一个定时队列任务。扩展从 Orders 排序的店铺商品展示页开始，只读取监控池中商品 ID 对应的 IXSPY 最近 7 日日增量；需要时翻到同一店铺的后续商品展示页，不打开商品详情页。店铺页采集逐个展开卡片趋势并校验图表商品 ID，不打开全年数据，也不会并行操作同一个趋势面板。隔离 Chrome 中的采集窗口保持可见但不抢键盘焦点；若 AliExpress 要求验证或 IXSPY 登录过期，才将对应页面显示到前台并等待人工处理。

店铺页采集最多访问 10 页，并设置单页与整项时限。未找到的商品或未读到的日期写为待补状态；若页面后来可读，可在下一次店铺页任务中补齐。明确看到的 `0` 是已确认的日增量，待补 `0` 不计入已确认店铺汇总。单商品详情页只用于人工发起的诊断，不参与定时店铺任务。

后续店铺页再次遇到 AliExpress 验证时，扩展会保留当前标签、暂停队列并通知用户；不会自动处理验证码。验证完成并回到正常店铺页后继续当前店铺任务。任务完成时仅关闭采集标签，不影响用户日常 Chrome。

## 第二台电脑采集

将本目录扩展加载到第二台电脑的 Chrome，并在该电脑登录监控台、AliExpress 和 IXSPY。当前扩展允许连接主机 `192.168.66.107:3000`；请在路由器中为主机保留此 DHCP 地址。第二台电脑使用 `http://192.168.66.107:3000/?browser_collection=1` 打开监控台，扩展会把队列 API 指向同一地址。Chrome 保持运行、采集窗口可见且不要最小化；窗口不需要持续获得键盘焦点。需要由第二台电脑执行时，在监控台采集电脑选择器中选中它并点击“开始采集”；未被选中的电脑只报告在线状态，不会领取任务。验证码仍由用户处理。

任务所有权由监控台的单机选择控制；不需要为了队列独占而关闭另一台电脑的 worker。调度器和数据库仍运行在主机。若主机 LAN 地址变更，需要同步更新 `manifest.json` 中的 LAN 地址、重新加载两台电脑上的扩展，并重新打开监控台。

扩展不会导出 Cookie、保存密码、自动处理验证码或调用内部订单接口。

## 托管 Backend 配置

编辑 `config.js`，把 `globalThis.ALIEXPRESS_MONITOR_API_BASE` 改成托管 FastAPI 的 HTTPS origin；同时在 `manifest.json` 的 `host_permissions` 中加入同一 origin 的精确匹配，例如 `https://monitor-api.example.com/*`。重新加载扩展后，人工补采和每日浏览器采集都会写入云端 Backend。

Render 部署时，Frontend 的 `VITE_API_BASE_URL` 也必须填写同一个 Backend HTTPS origin。扩展和 Frontend 必须指向同一个 Backend，否则会出现“商品尚未加入监控”或看不到历史快照。

## 店小秘链接交接

监控台的“采集到店小秘”按钮会创建交接队列。扩展只在已登录的
`https://www.dianxiaomi.com/web/productCrawl/dataAcquisition` 页面中，使用页面可见的
“链接采集”文本框和“开始采集”按钮提交商品链接。

这不是店小秘官方 API，也不会调用或修改第三方“店小秘助手”扩展。扩展不会读取 Cookie、密码或 Token，
不会绕过登录、协议确认、验证码或平台访问限制。提交后监控台显示“采集中”，表示链接已交给店小秘页面，
不等同于店小秘已经完成商品资料采集。

使用前请在 Chrome 中重新加载本目录扩展，并保持店小秘已登录。若页面要求确认采集协议或重新登录，
任务会停在“待人工确认”；完成正常操作后，在监控台点击“人工确认后重新排队”。

如果不希望任务使用日常 Chrome，可以双击项目根目录的
`setup-dianxiaomi-worker.bat`。它会创建独立的
`%LOCALAPPDATA%\AliExpressMonitor\DianxiaomiProfile` 配置并只加载本项目扩展。
店小秘官方的“店小秘助手”需要在这个隔离窗口的 `chrome://extensions`
中单独加载或安装一次，不能直接复用日常 Chrome 的扩展安装状态。
首次在该窗口登录监控台、店小秘、加载店小秘助手并确认协议；之后使用
`start-dianxiaomi-worker.bat`，脚本只会重启自己的隔离配置并在后台最小化运行，
不会关闭普通 Chrome。
普通 Chrome 中的扩展不会领取店小秘队列；只有带有
`?dianxiaomi_worker=1` 的独立工作配置才会执行队列。

扩展也监听本地或托管监控台中的“采集到店小秘”按钮。独立工作配置会每 30 秒检查一次同一地址的队列；如果在工作配置自己的监控台页面点击按钮，则会立即唤醒队列。首次切换到另一个 Backend 时，在扩展弹窗登录一次对应的监控台账号。更新扩展后请在 `chrome://extensions` 点击“重新加载”。
商品销量采集
------------

定时采集在 AliExpress 店铺商品列表页点击监控商品卡片的 IXSPY 趋势入口，展开「更多」趋势面板并读取「增量」模式中的最近 7 日可见值；图表上的商品 ID 必须与卡片 ID 一致。未在店铺页读到完整 7/7 时，保留已读点并将缺失日期标记待补，不启动商品详情页任务。累计售出数、`sold/orders` 总量以及相邻快照差值不会写入日销量指标。

提示框日期和值必须可见且可解析才会导入；明确显示的 `0` 和负增量修正值会原样保留。定时店铺任务的缺失日期保存暂记 `0`，但 `is_estimable=false`，与真实 `0` 区分且不计入汇总。最近 7 个日期全部有值时才标记 7/7 完整，否则保留实际覆盖并允许之后重试。日销量历史只将 IXSPY 直接日增量视为已确认；旧快照和旧估算记录仍保留，但不再参与当前汇总。

扩展只读取当前店铺页或人工诊断商品页可见的 IXSPY 图表提示框；不调用隐藏接口、内部订单接口、Cookie 或 Token，也不会自动处理验证码。IXSPY 要求登录或 AliExpress 要求验证时，队列会暂停并等待人工正常完成。
